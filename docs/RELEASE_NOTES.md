## 0.2.8 —— 把声音对齐，把门开全

这一版收了四件事：**声音不同步**、**有的视频导入失败**、**抖音拍视频时音频没被替换**、
以及日志太吵看不清重点。

### 一、声音不同步：生产端和消费端速率从来就不相等

消费端是硬实时的 —— 麦克风每 20ms 来要 1280 字节，一秒 50 次，不多不少。
生产端是解码线程，节奏跟着视频帧走：

| 宿主帧率 | 一帧视频补一包音频 | 相对实时 |
|---|---|---|
| 30 fps | 30 × 23ms ≈ 0.70 秒/秒 | **0.70×，长期抽干** |
| 60 fps | 60 × 23ms ≈ 1.39 秒/秒 | **1.39×，持续堆积** |

原来的上限是 `_audioBytesPerSecond * 2`（2 秒）。一旦堆到 2 秒，缓冲就不再增长，
但也不回落 —— 于是延迟被**恒定锁在 2 秒**。这就是「音频不同步」的来源，
跟素材、跟宿主都无关。

改法是两头都动：

- **消费端**：超过 100ms 水位就把多出来的直接丢掉，把延迟拉回恒定 ~100ms。
  丢掉比留着好 —— 留着的每一字节都是「声音比画面晚」。
- **生产端**：一帧视频周期内按水位补包，最多 8 包，不再「一帧只补一包」。

```
音频: 缓冲超水位，丢弃 35280 字节拉回 100ms（累计 35280）
```

### 二、抖音拍视频：麦克风根本不走 AudioUnitRender

0.2.7 的日志里有一行一直被当成「知道了」放过去：

```
音频: 宿主使用 AudioQueue 录音（16000Hz 1ch），暂未接管
```

它出现在每一次进拍摄界面的时刻。同一次会话里还有 `AudioUnitRender 命中 3 处符号槽`，
但那三处（AwemeCore / RTCLive / byteaudio）是**直播、连麦**用的。
拍短视频走的是 `AudioQueueNewInput` —— 一个我们当时只挂了探针、不接管的口子。

结果就是：**抖音拍视频时「替换音频」完全空转，录进去的是真麦克风。**

0.2.8 把它接上了。做法是换掉宿主传给 `AudioQueueNewInput` 的回调和上下文：

```c
OSStatus st = gSLAQOrig(fmt, SLCamAudioQueueInputCallback, ctx, rl, mode, flags, outAQ);
```

回调触发时先用素材音频覆盖 `mAudioData`，再把宿主原来的回调叫起来 ——
buffer 的地址、长度、时序都没变，只有内容换了，宿主察觉不到。
建队列时立刻 `primeAudioFormat:` 登记格式，让解码线程提前把音轨挂上，
否则开头一两百毫秒只能出静音。

护栏（任何一条不满足就原样放行，不硬来）：

- 格式必须是线性 PCM，压缩格式没法逐包替换
- `sampleRate` / `channels` / `bytesPerFrame` 必须自洽，`bytesPerFrame < 64`
- 素材没音轨或还没解出数据 → 长度对不上 → **保持真麦克风**，绝不写半截
- 宿主音频已经在走 AVCapture → 让路，避免两条链路抢同一个 PCM 池

```
音频: 已接管 AudioQueue 录音（16000Hz 1ch 4B/帧）· 素材音 已就绪
音频: 已接管 AudioQueue 麦克风输入（16000Hz 1ch）
```

第一行在宿主建队列时打，第二行在第一次真的写进 buffer 时打。

### 三、有的视频导入失败

PHPicker 给的 URL 是**临时文件**，生命周期只到 completion handler 返回为止。
原来我们把导入丢进 `dispatch_async(main_queue)` 里做 —— handler 已经返回了，
文件随时可能被清掉。视频越大、导出越慢，撞上的概率越高，表现就是「有的能导入，有的不行」。

改成在 handler 内同步拷走，并且把 `preferredAssetRepresentationMode` 设为 `.current`
（默认的 `.automatic` 可能触发转码，转码既慢又可能失败）。

### 四、导入后当场体检

拷完先验一遍：有视频轨、能挂上 420f（退 BGRA）输出。判据和 `SLCamFeed` 建 reader 时
**完全一致** —— 用同一套条件才不会出现「体检通过、真跑起来却黑屏」。

不通过就当场删掉并说清原因，而不是在列表里留一条点了没反应的死条目。

```
导入: xxx.mp4 解码不可用，已删除
```

### 五、日志降噪

同一份日志里，`float button mounted at {28, 216.31}` 出现 40+ 次，
`moved to top window` 30+ 次，启动时还有 6 行「跳过 …签名不是单指针参数」。
真正有用的行被淹在里面。

| 原来 | 现在 |
|---|---|
| 每次挂载都打一行 | 位置没变就不打，每 50 次补一行心跳 |
| 每次换窗口都打一行 | 同一类窗口只打第一次，每 50 次补一行心跳 |
| 每个跳过的签名一行 | 合成一行，方法名逗号分隔，一条不少 |

另外 `feed 管线就绪 (video=Y audio=N)` 里的 `audio=N` 一直有歧义 ——
它说的是「宿主没通过 AVCapture 来要音频」，跟素材有没有音轨是两回事。
现在换素材时会单独打一行 `feed 素材音轨: 有/无`，两行连起来读就不会误判。

### 装上之后验证这三件事

1. **通话里唇音是否对得上**（目标延迟约 100ms）—— 之前是恒定的 2 秒
2. **抖音拍视频时，录出来的声音是不是素材音** —— 之前是真麦克风
3. **替换音频开关关掉，应该是完全静音**，不是环境声

## 装法

自签注入：把 `ShenglinVcam-v<版本>.dylib` 注入目标 App 的 IPA 后重签安装。
越狱环境直接装 `ShenglinVcam-v<版本>.deb`。

> 本包与底包（声临）**包名和 dylib 名完全一致**，装这个会把底包覆盖掉。
> 两个都要用的话别同时装。
