## 0.2.6 —— 只加诊断，不改行为

0.2.5 修好了闪退，但 QQ 通话时音频链路**一条日志都没有**。
翻代码发现根因不在逻辑，在**可见性**：`SLCamAudioUnitRender` 里每一道提前返回都是静默的，
日志上「hook 根本没被调用」和「被某道门挡掉了」长得一模一样，没法定位。

这一版只加埋点，**功能行为和 0.2.5 完全一致**。

### 新增的日志

**1. 证明 hook 有没有被调用**

```
音频: AudioUnitRender 首次被调用 bus=0 frames=1024 bufs=1 st=0
音频: 首次出现 bus=1 输入调用 frames=1024 bufs=1 st=0
音频: 心跳 调用 3000 次 / bus=1 1500 次
```

`AudioUnitRender` 是播放和录音共用的。播放方向每 10ms 一次，所以**只要这个 hook 被调用，
第一行几乎必然会出现在日志里**。这行没有 → 说明调用点压根不经过我们的符号槽。

**2. 每道门第一次拒绝时留一行**

```
音频: 放行 —— 宿主渲染没成功 st=...
音频: 跳过 —— 当前没开启替换
音频: 让路 —— 宿主音频走 AVCapture，交给那条链路
音频: 跳过 —— 这个 unit 的输入元素没开，不是麦克风采集
音频: 跳过 —— 拿不到输入格式（StreamFormat 查询失败）
音频: 跳过 —— 输入不是线性 PCM（formatID=... ）
音频: 跳过 —— unit 缓存已满（上限 8）
```

每行只出现一次，不会刷屏。

**3. 会话加输出时的累计计数**

```
音频: 会话加输出时 AudioUnitRender 累计调用 12 次 / bus=1 0 次
```

这条最关键：如果通话开始、会话都加完输出了，累计还是 **0 次**，
那就彻底排除「被过滤条件挡掉」，问题一定在「调用点不在我们扫到的镜像里」。

**4. 符号扫描：命中要打镜像名，认证 GOT 跳过要计数**

```
符号: 命中 AudioUnitRender ← QQ
符号: 扫过 6 个 App 镜像，命中 1 处，认证 GOT 跳过 0 处
```

arm64e 的 `__AUTH` / `__AUTH_CONST` 段里是 PAC 认证指针，写裸地址会被校验拦下、直接崩，
所以这类段我们整段跳过。但以前**跳过了多少不记录**，于是分不清
「镜像里没有这个槽」和「槽在认证段里被跳过了」—— 这两种情况的修法完全不同。
现在有了 `认证 GOT 跳过 N 处`。

**5. 素材音轨单独探测**

```
feed 素材音轨: 有（1793274336.mp4）
```

以前 `feed 管线就绪 ... (video=Y audio=N)` 里的 `audio=N` 很容易被误读成「素材没音轨」。
其实那个 N 只表示「宿主还没来要音频」—— 音频输出要等宿主第一次调 `audioForFormat:`
才会创建，是鸡生蛋的设计，启动时必然是 N。现在素材到底有没有音轨单独一行说清楚。

### 怎么读这份日志

| 日志表现 | 结论 | 下一步 |
|---|---|---|
| 出现 `AudioUnitRender 首次被调用` + `AudioUnit 输入 ...` + `已接管` | 链路通了 | 收工 |
| 出现 `首次被调用`，但全是 `bus=0`，且某道 `跳过 ——` 出现 | 被过滤条件挡掉 | 按那行日志放宽条件 |
| **完全没有** `AudioUnitRender 首次被调用` | 调用点不在 `.app/` 镜像里 | 只能改 inline hook |
| `认证 GOT 跳过 1 处` 以上 | 槽在 arm64e 认证段 | 需要 PAC 签名后才能写 |
| `音频: 会话加输出时 ... 累计调用 0 次` | 同上，彻底排除过滤条件 | 同上 |

## 装法

自签注入：把 `ShenglinVcam-v<版本>.dylib` 注入目标 App 的 IPA 后重签安装。
越狱环境直接装 `ShenglinVcam-v<版本>.deb`。

> 本包与底包（声临）**包名和 dylib 名完全一致**，装这个会把底包覆盖掉。
> 两个都要用的话别同时装。
